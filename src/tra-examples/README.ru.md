# Примеры TRA — JDK 11+

Это готовые примеры на fi.uef.cs.tra. TRA — основной API графовых/древовидных тем, включая анализ графов, паросочетание и поток. Прежние 31 исходник без библиотеки сохранены; переведённые варианты доступны как дополнительные сравнения.

Распакуйте ZIP. Оставьте шестнадцать файлов `.java` рядом с `traj.jar`. Откройте терминал в этой папке и выполните любой пример:

```bash
java -Dfile.encoding=UTF-8 -cp traj.jar TraGraphExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraGraphDataExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraRecursiveDfsExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraDfsExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraTraversalExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraBfsExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraTreeExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraPriorityQueueExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraComponentsExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraTopologicalExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraDijkstraExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraFloydWarshallExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraMinimumSpanningTreeExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraGraphCutsExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraBipartiteMatchingExample.java
java -Dfile.encoding=UTF-8 -cp traj.jar TraMaxFlowExample.java
```

Команды одинаковы для Windows, macOS и Linux. В IDE добавьте `traj.jar` как библиотеку. Каждый файл содержит собственный main и вспомогательные классы и не зависит от остальных примеров. В `expected-output.txt` находится вывод, проверенный с этим JAR.

- **TraGraphExample:** создание `DiGraph`/`Graph`, добавление вершин и рёбер, `vertices()`, `neighbors()`, `getColor()` и `setColor()`. Неориентированное ребро добавляется один раз: Graph обеспечивает соседство в обе стороны.
- **TraDfsExample:** рекурсивный DFS, GREY/PRE при входе, POST/BLACK при завершении, продолжение родителя после возврата, родители и корни. `traverse(graph, start, false)` обходит достижимую часть; `true` продолжает с оставшихся WHITE-вершин. Корни направленного леса не являются компонентами сильной связности.
- **TraBfsExample:** `LinkedQueue<Vertex>`, GREY до добавления в очередь, BLACK после просмотра соседей, кратчайшие расстояния по числу рёбер и путь по родителям. Для недостижимой вершины расстояние -1, путь пустой. Извлечение из очереди само по себе не меняет цвет на BLACK.

Оба метода обхода принимают `AbstractGraph` и работают с `DiGraph` или `Graph`. Для непустого графа старт должен принадлежать этому графу; для пустого передайте null. Каждый запуск заново устанавливает цвета. В таблицах родителей и расстояний используются объекты вершин: одинаковые метки не объединяют вершины.

В этой версии TRA класс `DiGraph` допускает петли, а `Graph` отклоняет их при добавлении ребра.

Показанные PRE/POST и порядок обнаружения соответствуют `neighbors()` в приложенном JAR. Другой порядок соседей может изменить родителей DFS, списки обхода и выбор среди равных кратчайших BFS-путей, но не кратчайшие расстояния. Комментарии исходников и вывод программы общие для трёх языков интерфейса.

Полный DFS занимает Θ(V + E) времени и O(V) дополнительной памяти с результатами и стеком. Обход достижимой части DFS и BFS занимает Θ(V + R + A_R), включая начальную установку цветов и, для BFS, расстояний. R — число достижимых вершин, A_R — количество просмотренных исходящих записей смежности. Хранение входного графа в дополнительную память не включено. Соседи не сортируются, все списки смежности перед обходом не копируются.

Предоставленный `traj.jar` включён без изменений (SHA-256 `589c64b49dd8fa77fa1fb9f99d252bf475c180be437a70d81208f4e9f70f3423`). В нём также есть старый пакет `fi.joensuu.cs.tra`; эти примеры последовательно используют `fi.uef.cs.tra`. Документация библиотеки находится внутри JAR в `javadoc/fi/uef/cs/tra/`.

- **TraGraphDataExample:** число исходящих соседей хранится в `Map<Vertex, Integer>`, структура графа — в TRA. Граф A/B/C/D соответствует основному уроку; две вершины X показывают различие ключей по идентичности. Подсчёт сохраняет цвета и структуру графа, занимает ожидаемое Θ(V + E) времени и O(V) памяти Map.

Основной урок показывает A→B (5.0f), A→C (2.0f), B→C (1.0f) и изолированную D. Рисунок, списки соседей и TraGraphExample.createDirectedGraph() сверяются с реальным JAR. Второй аргумент float в addEdge — вес, int — цвет.

Основной базовый DFS — **TraRecursiveDfsExample**: собственный итератор TRA и отдельная IdentityHashMap visited, без изменения цветов. i считает обработанных соседей; итератор передвигается вызовом next() ещё до запуска ребёнка. После возврата продолжается тот же итератор родителя. Ожидаемое время полного обхода Θ(V + E), достижимой части с подготовкой visited — Θ(V + R + A_R); дополнительная память O(V). Порядок учебных графов проверен на приложенном JAR и не является гарантией сортировки меток.

**TraTraversalExample** — общий источник цветного обхода, классов рёбер и практики: стабильные ID по идентичности, карты данных, физические Edge, времена, цикл, пути и топологическая сортировка с отказом при цикле, неполном DFS или BFS. Очередь — TRA LinkedQueue. Сортированные списки соседей подготавливаются явно за O(V + E + Σ d(v) log(d(v) + 1)) времени и O(V + E) памяти. После подготовки ядро полного обхода Θ(V + E), достижимой части Θ(R + A_R). Вся дополнительная память со списками и классами рёбер O(V + E); сортировка не выдаётся за линейную работу обхода.

TraBfsExample создаёт тот же Graph A–H, что базовый рисунок, и печатает обнаружение, расстояния и кратчайший путь A–H. Обобщённый search также поддерживает DiGraph, недостижимые цели и пустые графы. GREY ставится до очереди, BLACK — после всех соседей; само извлечение не завершает вершину.

**TraTreeExample** создаёт то же BTree A–G, что рисунок, и заполняет PRE/IN/POST за один обход. Высота в рёбрах: пустое -1, лист 0, цепочка из n узлов n-1. Каждый traverse/size/height занимает Θ(n) времени; стек непустого дерева O(h+1), краткий null-вызов добавляет один кадр (пик h+2). Результаты добавляют O(n). В Tree/TreeNode используются первый ребёнок и следующий сосед: R имеет детей X/Y/Z. BTree не является автоматически BST/кучей и отличается от B-дерева внешней памяти.

**TraPriorityQueueExample** импортирует fi.uef.cs.tra.PriorityQueue, использует значения учебной кучи, сохраняет повтор 3, показывает peek без удаления и poll с удалением, а также null для пустой очереди. Добавление null запрещено. Для задач используется конструктор с ёмкостью и компаратором. Итератор не обещает сортировку или точное расположение как на рисунке. Просмотр priorityOrder копирует очередь и вызывает poll, сохраняя исходную очередь за O(n log n) времени и O(n) памяти. peek O(1), poll O(log n), offer амортизированно O(log n) с учётом расширения массива.

**TraComponentsExample** принимает неориентированный Graph. Цвета сбрасываются один раз, затем из каждой WHITE-вершины запускается DFS: один список результата — одна компонента. Фабрика и рисунок содержат 0—1, изолированную 2 и 3—4. У пустого графа ноль компонент. Отдельная полная проверка циклов исключает то же физическое родительское Edge: одно ребро не даёт цикл, треугольник даёт. Оба метода завершают все корни с BLACK за Θ(V + E) времени и O(V) дополнительной памяти с результатами и стеком. Меняются только цвета вершин, каждый запуск создаёт новые списки.

**TraTopologicalExample** принимает DiGraph и собирает POST полным DFS. Исходящее ребро к GREY, включая петлю, вызывает `IllegalArgumentException("cycle")`. POST разворачивается и возвращается только после успеха всех корней; изолированная вершина включается, пустой граф даёт пустой порядок. Цикл в несвязной части тоже запрещает весь порядок. При ошибке цвета могут быть WHITE/GREY/BLACK, но новый запуск сбрасывает их, частичный порядок наружу не выходит. Время Θ(V + E), дополнительная память O(V). Рёбра, веса и метки сохраняются. Фабрики DAG и циклического графа совпадают с общей визуализацией.

Для путей по родителям и свидетельства цикла используется **TraTraversalExample** в рабочей области применений. `path(state, target)` возвращает путь от начального старта или пустой список для недостижимой/чужой цели; старт → старт имеет ноль рёбер. DFS даёт найденный путь, BFS минимизирует число рёбер. Полный лес не создаёт достижимость: другие корни сохраняют расстояние -1 от начального старта и собственную глубину ноль. В DiGraph соседи исходящие, деревья его леса не являются SCC. Возможны разные правильные пути, списки компонент и топологические порядки; проверяются свойства графа, а не один точный список. Общая анимация отдельно готовит сортированных соседей с указанной выше стоимостью; два новых примера не сортируют.

**TraDijkstraExample** принимает Graph/DiGraph и старт этого графа (null только для пустого). Проверяются все Edge, даже недостижимые: только конечные неотрицательные веса. TRA PriorityQueue создаётся с ёмкостью и компаратором. Неизменяемые записи содержат Vertex и расстояние double; улучшение добавляет новую запись, устаревшая пропускается. Поля Vertex в очереди не меняются. Время O(V + E log(E + 1)), дополнительная память O(V + E) с таблицами и ленивой очередью. Граф A/B/C/D/E даёт расстояния 0/3/1/4/INF и путь A→C→B→D; E изолирована.

**TraFloydWarshallExample** принимает Graph/DiGraph, назначает внешние индексы настоящим объектам Vertex и строит матрицы расстояний/следующего шага из исходящих Edge. Диагональ ноль — пустой путь, +∞ — отсутствие/недостижимость. Внешний цикл k рассматривает промежуточные вершины. Конечные отрицательные веса разрешены. Любая вычисленная отрицательная диагональ отклоняет весь результат через `IllegalArgumentException("negative cycle")`, включая несвязные отрицательные циклы и петли: частичная матрица/путь не возвращается. Математически конечного минимума нет только у затронутых пар; здесь выбран отказ от всего результата. Отрицательное неориентированное ребро допускает неограниченное уменьшение веса при движении туда-обратно и тоже отклоняется. Время O(V³ + E), дополнительная память O(V²). A→B:5, B→C:-2, A→C:10 дают путь A→B→C с весом 3; D изолирована.

Дейкстра: `distanceTo(target)` / `pathTo(target)`. Флойд: `distance(from, to)` / `path(from, to)`. Используется идентичность, а не метка или Vertex.index. Чужие/null вершины запросов отклоняются. Недостижимость — Double.POSITIVE_INFINITY (вывод INF) и пустой путь; вершина в себя — расстояние 0 и путь из одной вершины без рёбер. Запрос пути занимает O(длины пути); разные равноценные пути допустимы. Все поля входного графа, включая цвета, сохраняются, результаты повторных запусков независимы.

Числовая политика: конечные float из Edge.getWeight() суммируются в double, улучшения сравниваются строго, бесконечные подпути Флойда не складываются. Суммы Float.MAX_VALUE на маленьких графах конечны в double; 0.1f всё равно остаётся двоичным приближением. Вычисления с плавающей точкой не доказывают отсутствие отрицательного цикла при почти полном взаимном сокращении весов; учебные примеры используют маленькие точно представимые значения. Проверки используют точные двоичные дроби и допуски по масштабу/ULP для расстояний и сумм путей. NaN и обе бесконечности запрещены во входе. Пиши 5.0f в addEdge: целый аргумент выбирает цвет. BFS остаётся сравнением для минимального числа рёбер, а не произвольной суммы весов.

**TraMinimumSpanningTreeExample** принимает неориентированный Graph и возвращает Result: vertices(), edges(), components(), totalWeight(), isSpanningTree(). Список содержит настоящие входные Edge, а не искусственные обратные или фиктивные рёбра. Несвязный вход даёт минимальный остовный лес: V вершин и C компонент требуют V-C выбранных рёбер, изолированные вершины учитываются. Пустой граф имеет ноль компонент/вес 0 и не называется деревом; одна вершина — дерево без рёбер. Списки только для чтения, каждый запуск создаёт новый результат и сохраняет поля графа. Объекты остаются изменяемыми объектами входа, это не глубокая копия.

Прим хранит граничные Edge в TRA PriorityQueue с ёмкостью и компаратором. Ребро с двумя достигнутыми концами пропускается, после завершения компоненты выбирается новый корень. Направление хранения концов Graph не важно; веса во время нахождения в очереди не меняются. Краскал сортирует копию Graph.edges(), где каждое физическое ребро встречается один раз, и использует собственные массивы union-find со сжатием путей/рангами и внешними индексами Vertex по идентичности. Оба сохраняют цвета и Vertex.index/weight. Время каждого O(V + E log(E + 1)), дополнительная память O(V + E) при ожидаемом O(1) карт/множеств по идентичности; у Прима каждое физическое ребро добавляется в очередь не более одного раза.

Конечные отрицательные/нулевые веса и равенства допустимы; алгоритмы не обязаны выбирать одинаковый набор или порядок рёбер. NaN и обе бесконечности запрещены во всём графе. Float суммируется в double с обычным округлением. Связный пример весит 4; добавление изолированной E и F-G:-2 даёт три компоненты, четыре ребра и вес 2. В A-B:2, A-C:2, B-C:1 минимальный остов весит 3, а дерево кратчайших путей из A выбирает два ребра веса 2 с суммой 4. Цель MST — сумма рёбер, а не расстояния от старта. Старый JDK-пример сохранён для сравнения и отклоняет несвязный вход.

**TraGraphCutsExample** принимает Graph и игнорирует веса. Полный DFS возвращает настоящие точки Vertex и мосты Edge всех компонент. tin считает входы; low — самый ранний вход через спуск по дереву и не более одного неродительского обратного ребра. Посещённый сосед даёт tin, вернувшийся ребёнок — low. Некорневая точка: low[child] >= tin[v]; мост: low[child] > tin[v]; корневая точка: хотя бы два ребёнка DFS. Пропускается тот же физический parent Edge. Пустота, изоляция и несвязность допустимы. Ожидаемое O(V + E) времени/O(V) памяти; сортировка подписей вывода отдельно. Чужие вершины запросов времени отклоняются.

**TraBipartiteMatchingExample** принимает Graph и явный список разных входных Vertex левой доли; правая — остальные. Проверяет пересечение долей каждым ребром, доли автоматически не определяет. Рекурсивные чередующиеся пути переназначают партнёров, новый seen создаётся для каждого левого корня: находится максимум пар, а не просто нерасширяемый набор. Веса игнорируются. Возвращаются настоящие Edge, списки долей и симметричный partnerOf: null для свободной, ошибка для чужой вершины. Ожидаемое O(V + E + L·E) времени/O(V) памяти. В L0:[R0,R1], L1:[R0] L0 перемещается на R1; изолированная R2 свободна.

**TraMaxFlowExample** принимает DiGraph и разные входные исток/сток; пустой граф не содержит допустимых двух вершин. Учебная реализация принимает сохранённые float ёмкости Edge только как конечные целые [0, 1 000 000 000]. Отрицательные, дробные, неконечные и слишком большие значения отклоняются во всём графе без округления; затем используются точные long и проверяемые суммы. Десятичный литерал уже мог округлиться при сохранении float: проверяется сохранённое значение. Пиши addEdge(v, 3.0f), целый аргумент выбирает цвет. У каждого Edge отдельная прямая/отменяющая остаточная пара, в том числе при настоящих противоположных рёбрах. Отменяющий переход не обязан быть входным ребром; вход никогда не дополняется и не меняется. BFS использует TRA LinkedQueue. Результат: flowOn/capacityOf по Edge, value, sourceSide, cutEdges/cutCapacity, число обратных шагов; чужие Edge отклоняются. Ёмкость разреза равна значению потока. Ожидаемое O(V + E + V·E²) времени/O(V + E) памяти; новая карта родителей каждого BFS не обнуляет все изолированные вершины.

Все три алгоритма сохраняют поля и структуру входа, возвращают списки только для чтения с настоящими объектами и независимые результаты повторных запусков. Оценки предполагают ожидаемое O(1) доступа по идентичности. В перенаправлении остаточный x→a отменяет a→x, хотя x→a нет во входе; итоговый поток 2, по a→x идёт 0. SCC и новые задания остаются отдельной работой. Старые массивы/матрицы сохранены в закрытых сравнениях со своими контрактами и оценками.
