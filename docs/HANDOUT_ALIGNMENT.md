# Alignment with dsaII_handout.pdf

Source: **Data Structures and Algorithms II**, Simo Juvaste, University of Eastern Finland, autumn 2025, 89 pages. The author's name is verified from the supplied handout's title page and displayed beside its filename on the site. Page numbers below refer to PDF pages, which match the printed page numbers. The handout is used as a teaching source; its PDF is not included in the published site files.

The project now has 22 topics and 31 standalone Java files. Explanations are available in Russian, Finnish and English. The Java code is shared across languages: download a file and run `java ClassName.java` with JDK 11 or newer, without the course TRA library.

DFS also has a separate trial exercise using the user-supplied `traj.jar`: students implement a recursive count of reachable vertices. The kit works with JDK 11 or newer, compiles solutions with --release 11 and is separate from the 31 complete examples: Solution.java is an unfinished template, while Check.java and GraphChecks.java provide local checking. All files and instructions in the three languages are included in the downloadable ZIP.

The main graph/tree downloads now contain 52 independent TRA teaching examples, arranged by topic. Each card shows one operation or algorithm step, a small input, its actual source-derived fragment, expected output and a short explanation; complete files and advanced steps are separately expandable. The catalogue covers graph creation/reading, identity-keyed data, simple DFS, PRE/POST, separate colours/times/edge types, BFS/distances/paths, components/cycles/topological sorting, separate tree and queue operations, weighted paths, separate Prim/Kruskal/DSU, tin/low/bridges/articulation, matching and incremental flow lessons. The supplied unchanged JAR, expected output, English/Finnish README files and per-topic command indexes are packaged with the sources for Java 11+. The previous sixteen multi-purpose TRA files remain technical references for visualisation regression checks, outside the student ZIP.
## Changes

The migration of graphs and trees to TRA as the primary model is documented separately: [file and stage map](TRA_MIGRATION.md), [verified API contracts](TRA_CONTRACTS.md). As of 25 November 2026, stages 1–6 and the teaching-example rewrite are complete: contracts, graphs/Map, traversals, trees/priority queue, DFS/BFS applications, weighted shortest paths, minimum spanning forests and graph analysis. Stage 7 practice is complete: DFS reachable-count, BFS shortest-hop-distance/shortest-path, connected-component, BTree size/height and separate PRE/IN/POST kits are available; the final migration audit remains pending. A shared SHA-256 check protects the JAR when building the downloads; executable checks validate the API and algorithms against the library. Existing step-by-step visualisations are preserved.

- Added separate practical topics for List/Deque, Set and Map. The combined Set/Map topic remains as an introduction.
- Explained set operations, choosing hash-based or tree-based collections, iteration order, object equality, stable key fields and the special role of the TreeSet comparator.
- Added complete runnable examples to existing topics, replacing fragments with undefined `Vertex` objects, lists and unfinished branches.
- Added sections on weighted paths, spanning trees, graph analysis, algorithm strategies, strings and external memory.
- Each page identifies the corresponding handout sections and pages. Some material is an overview; a section reference does not imply complete coverage of its proofs or every algorithm.
- Added time and space analysis for factorial, naive and memoised Fibonacci, and DFS: work per call and across the entire run, recurrences, live counters, a comparison table and growth for n from 0 to 20. Total calls are separated from peak stack size, cache capacity from occupied entries, and Java algorithm memory from visualisation history. These are teaching metrics, not a benchmark.
- Expanded the final recursion quiz to 15 questions covering all four learning objectives: call mechanics, returns, tracing and complexity. It includes the stack, the next neighbour after a return, skipping visited vertices, PRE/POST, disconnected graphs, memoisation and visited initialisation. Each correct answer and each mistake is explained. Students can revisit earlier questions without changing checked answers, review results and start a new attempt. All material is translated; switching languages preserves the question, answers and execution state.
- Added four trees to recursion (§1.3) and complexity for T(n−1)+1, 2T(n/2)+1, 2T(n−1)+1 and 2T(n/2)+n, with base case T(1)=1. Labels on the left distinguish maximum depth from the number of levels; labels below explain width, and a table sums call work by level. The two halving trees have the same shape but yield Θ(n) or Θ(n log n), depending on each node's own work. Every node is shown individually, with scrolling and manual zoom; revealing levels is explicitly separated from Java execution order. Four Java snippets return abstract work units, rather than machine instruction counts or elapsed time. They supplement the 31 standalone downloadable files.

## Clarifications compared with a literal pseudocode translation

1. **Set in §1.6 is an abstract interface.** `union` and `member` are not methods of the standard `java.util.Set`: the examples use a copy plus `addAll`, and `contains`. `retainAll` and `removeAll` mutate the receiver; the examples preserve the original set.
2. **Dijkstra and PriorityQueue.** The handout uses a specialised queue that supports priority updates. JDK PriorityQueue has no decrease-key operation. The example adds a new immutable entry and checks for stale entries; its complexity bound describes this specific implementation.
3. **Floyd–Warshall, page 37.** In the printed fragment, the `j` loop starts at 1. The site implementation processes all destination vertices, including index 0. A dedicated case checks a shortest path to vertex 0 that improves through an intermediate vertex.
4. **LinkedList and two pointers.** Repeated indexed access can invalidate a linear bound. The implementation uses iterators, appends remaining tails completely and removes duplicates within the inputs.
5. **Connectivity and direction.** Ordinary component traversal is not presented as an algorithm for strongly connected components. Directed cycle detection uses three colours, and topological sorting rejects cycles.
6. **Maximum versus maximal matching.** Explanations distinguish maximum-cardinality matching from a matching that merely cannot be extended. The augmenting-path example finds a maximum matching.
7. **Approximate matching.** Initialising the row with zeros corresponds to searching within a text, rather than the edit distance between two complete strings. The test enumerates substrings and compares the result with an independent edit-distance reference.
8. **DFS scope and memory preparation.** Full traversal with adjacency lists takes Θ(V + E), including the outer loop. With `visited` prepared in advance, `dfs(start)` visits R reachable vertices and reads Aᵣ neighbour entries in Θ(R + Aᵣ) time. The displayed `traverse` first allocates and zero-initialises `boolean[V]`, so even without the outer loop its time is Θ(V + R + Aᵣ). Stack space is O(R), the shared `visited` structure is Θ(V), and PRE/POST use O(R); total additional space is O(V), excluding the input graph.

## Addition: detailed DFS and BFS

Added shared settings, independent cursors for the two algorithms, a comparison of completed runs and five application scenarios. A separate 12-question quiz uses fixed graph states and is independent of the lab's current step. Translations, selections and answers are preserved when switching languages. Java and the model are compared across every teaching graph, start, scope, neighbour order and both algorithms.

Memory clarification: the full traversal core uses O(V) working space. If all edge classes are retained, they are an O(E) result, making total space O(V + E), excluding the input and animation history. The classes are not automatically applied to BFS; a directed traversal forest is not called an SCC decomposition.

### Trial graph exercise with TRA

The exercise supplements directed graphs (§2.1–2.2), DFS (§2.3) and recursion (§1.3). The site presents the task, a directed graph, expected results and run instructions. ### Trees and heap: stage 4

English READMEs accompany RU/FI/EN site content and feedback. Existing print-based examples, traversal visualisations and metric tasks are preserved.
