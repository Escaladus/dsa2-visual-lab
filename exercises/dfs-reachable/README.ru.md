# Задание 1: сколько вершин достижимо?

В файле `Solution.java` напишите один метод рекурсивного DFS:

```java
public static int reachableCount(Vertex start)
```

Метод должен вернуть количество **разных вершин, до которых можно дойти из start по направлению рёбер**. Сам start тоже считается. Метки вершин могут совпадать: считаем вершины, а не разные названия.

## Пример

Направленные рёбра: `0→1, 0→2, 1→3, 2→3`. Вершина `4` изолирована.

- Старт `0`: ответ **4**. Вершина `3` учитывается один раз, хотя к ней ведут два пути. Вершина `4` недостижима.
- Старт `3`: ответ **1**, потому что исходящих рёбер нет.

## Условия

- `start` не равен null. Граф небольшой, направленный, без весов и параллельных рёбер. Возможны циклы и петли.
- Проверяющая программа сама создаёт граф и перед вызовом устанавливает всем вершинам `AbstractGraph.WHITE`. Не сбрасывайте цвета внутри рекурсивных вызовов.
- Найденные вершины помечайте `AbstractGraph.GREY` или `AbstractGraph.BLACK`. Недостижимые оставляйте WHITE. Для этого задания достаточно одной пометки посещения; полный обход с тремя состояниями не требуется.
- Используйте рекурсивный DFS. Можно добавить вспомогательные методы. Вершины и рёбра изменять нельзя; метки не обязательно уникальны.
- Верните целое число. Проверяется возвращаемое значение, а не печать в консоль. Порядок соседей на ответ не влияет.

## Как выполнить и проверить

Нужен **JDK 11 или новее**. Сначала распакуйте ZIP. Откройте терминал **внутри папки `dfs-reachable`**, где рядом лежат `Check.java`, `GraphChecks.java`, `Solution.java` и `traj.jar`.

```bash
java -Dfile.encoding=UTF-8 Check.java ru
```

Другие языки сообщений: `java -Dfile.encoding=UTF-8 Check.java en` и `java -Dfile.encoding=UTF-8 Check.java fi`.

Меняйте только `Solution.java`, сохраняйте файл и повторяйте ту же команду. В исходном шаблоне специально оставлено исключение TODO: первый запуск проверяет готовность окружения и сообщает, что решение ещё не написано. Результаты не блокируют новые попытки. Чтобы начать с пустого шаблона, возьмите исходный `Solution.java` из ZIP.

Проверка компилирует сохранённое решение с приложенным JAR и запускает 10 групп: изолированный старт, цепочка, разветвление, цикл, несвязность, направление рёбер, два пути в одну вершину, петля, одинаковые метки и 30 дополнительных воспроизводимых графов. На группу выделяется отдельный процесс, 5 секунд и ограниченная память/стек. Ошибка компиляции, исключение, зависание, неверное количество, неправильные цвета и изменение графа объясняются отдельно. Временные скомпилированные файлы удаляются; после ошибки компиляции старое решение не запускается.

В IDE добавьте `traj.jar` как библиотеку, редактируйте `Solution.java` и запускайте `Check.main`, указав папку задания как рабочую директорию.

## После решения

Объясните, когда ставится пометка, почему обход завершается на цикле и почему сходящиеся пути не дают повторного подсчёта. Выразите время через число достижимых вершин R и просмотренных исходящих записей смежности A_R. Оцените максимальный стек рекурсии. Создание графа и начальная установка WHITE выполняются проверяющей программой вне вашего метода.

Проверки подтверждают результат, цвета и сохранность структуры на конечном наборе примеров. Они не доказывают рекурсивность, правильность на всех возможных входах или оценку сложности. Рекурсию нужно проверить по коду, сложность — обосновать отдельно. Ограничение времени останавливает зависание и не является замером эффективности.
